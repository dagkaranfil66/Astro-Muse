Tengri Astroloji uygulamasındaki el falı görsel yükleme akışını düzelt.

SORUN:
Şu anda kullanıcı el falı için rastgele bir fotoğraf yüklese bile sistem yorum üretmeye devam ediyor. Yani görsel gerçekten avuç içi / el fotoğrafı olmasa bile el falı açılıyor. Bu güven problemi oluşturuyor.

HEDEF:
El falı yorumu başlamadan önce yüklenen görselin gerçekten el falına uygun olup olmadığını doğrula. Geçersiz görsellerde yorum üretme, kullanıcıya net uyarı göster.

YAPILACAKLAR:

1) GÖRSEL DOĞRULAMA KATMANI EKLE
El falı yorumundan önce ayrı bir validation step oluştur.
Sistem önce şu kontrolleri yapsın:
- Fotoğrafta gerçekten bir el / avuç içi var mı?
- Avuç içi yeterince net görünüyor mu?
- Görüntü çok bulanık mı?
- Görüntü çok karanlık mı?
- El kadrajda yeterince büyük mü?
- Rastgele nesne / alakasız görsel mi?

2) GEÇERLİLİK KURALI
Yalnızca gerçekten avuç içi tespit edilirse yorum üret.
Aksi durumda yorumu hiç başlatma.

Önerilen alanlar:
- isPalmDetected: boolean
- confidenceScore: number
- blurScore: number
- brightnessScore: number
- handCoverageRatio: number
- validationFailureReason: string | null

Önerilen mantık:
- isPalmDetected = true olmalı
- confidenceScore belirli eşik üstünde olmalı (ör. 0.75 veya 75)
- blur çok yüksek olmamalı
- brightness minimum eşik üstünde olmalı
- handCoverageRatio yeterli olmalı

3) GEÇERSİZ GÖRSELDE YORUM AÇMA
Eğer görsel uygun değilse el falı sonucu üretme.
Bunun yerine kullanıcıya hata/uyarı göster.

Örnek mesajlar:
- “Bu görselde net bir avuç içi tespit edemedik.”
- “Lütfen avuç içinin açıkça göründüğü net bir fotoğraf yükle.”
- “El falı için yalnızca elinin iç kısmını gösteren bir fotoğraf kullanılabilir.”

4) AI PROMPT / BACKEND GÜNCELLE
El falı üreten prompt veya backend akışında şu kural olsun:
- Validation başarılı olmadan yorum üretme
- Rastgele fotoğraf gelirse fal metni dönme
- Uygun olmayan görseller için structured invalid response dön

Örnek response mantığı:
{
  "valid": false,
  "reason": "Palm not detected"
}

veya

{
  "valid": true,
  "reason": null
}

Sadece valid=true ise palm reading oluşturulsun.

5) UI YÖNLENDİRME EKLE
El falı yükleme ekranında kullanıcıya şu yönlendirmeleri göster:
- “Avuç içini açık şekilde göster”
- “Tek el yükle”
- “İyi ışıkta çek”
- “Bulanık fotoğraf kullanma”
- “Elin ekranın büyük kısmını kaplasın”

6) ÖRNEK GÖRSEL / REHBER KUTUSU EKLE
Mümkünse yükleme alanında mini rehber veya örnek görsel kartı göster:
- doğru örnek
- yanlış örnek

7) GÜVENLİ FALLBACK EKLE
Validation servisi hata verirse sistem varsayılan olarak yorum üretmesin.
Fail-open değil fail-safe çalışsın.
Yani kontrol başarısızsa yorumu açmak yerine kullanıcıdan tekrar fotoğraf istesin.

8) TEST SENARYOLARI
Şunları test et:
- Rastgele masa fotoğrafı yüklenince yorum açılıyor mu? Açılmamalı.
- Siyah ekran / boş görsel yüklenince yorum açılıyor mu? Açılmamalı.
- Çok bulanık el fotoğrafında uyarı veriyor mu?
- Gerçek, net avuç içi fotoğrafında yorum açılıyor mu?
- Yetersiz ışıkta çekilen görselde kullanıcı yönlendiriliyor mu?
- Validation başarısız olduğunda sistem yanlışlıkla yine fal metni üretmiyor mu?

9) KOD YAPISI
Validation ve reading generation mantığını birbirinden ayır.
Önerilen akış:
upload image -> validate palm image -> if valid then generate palm reading -> else show retry UI

10) ÇIKTI
- Gerekli dosya değişikliklerini yap
- Hangi dosyalarda ne değiştiğini özetle
- Validation mantığını açıkla
- Kullanılan eşikleri belirt
- Production için güvenli olacak şekilde düzenle
